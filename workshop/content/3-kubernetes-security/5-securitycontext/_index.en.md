Workloads must satisfy Restricted while continuing to serve the application. Set minimal container privileges, identify writable paths, and test the runtime boundaries.

## Reduce execution privileges

If unintended code runs, the container should not automatically have root privileges or unrestricted root-filesystem writes. Settings apply at pod or container scope.

`runAsNonRoot` requires a non-root UID. `allowPrivilegeEscalation: false` restricts elevation through mechanisms such as setuid; it is not a complete sandbox. `RuntimeDefault` enables the runtime seccomp profile. Dropping capabilities removes unnecessary Linux privileges.

## Step 1: configure pod and container

Compare API `spec.template.spec.securityContext` and `containers[].securityContext` in `k8s/application.yaml`:

```yaml
securityContext:
  runAsNonRoot: true
  runAsUser: 10001
  runAsGroup: 10001
  seccompProfile:
    type: RuntimeDefault
containers:
  - name: api
    # See the full manifest for image and remaining fields
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      capabilities:
        drop: ["ALL"]
```

This is an excerpt. The full manifest generated by `scripts/render.py` already includes these application settings. After changing a pod template, apply and wait for rollout:

```bash
kubectl apply -f k8s/application.yaml
kubectl rollout status deployment/api -n notes
```

## Step 2: identify writable paths

Nginx needs PID/temp directories. The lab uses an unprivileged image on 8080 and a size-limited `/tmp` `emptyDir`, with PID/cache paths configured there. Do not make the entire root filesystem writable just to silence an error.

Python disables bytecode writes and reads the image's existing CA bundle. CPU/memory requests and limits constrain resource budgets, not every form of denial of service.

See [Dockerfile](/source/app/Dockerfile) and [render.py](/source/scripts/render.py). Non-root/Restricted execution does not replace dependency updates or application authorization.

## Verify container privileges

Inspect the API pod in EKS Console, then run:

```bash
kubectl exec -n notes deployment/api -- id
kubectl exec -n notes deployment/api -- python -c \
  'from pathlib import Path; Path("/app/should-not-write").write_text("test")'
```

Expect UID 10001 and a denied write (`Read-only file system` or permission error). API health must remain 200:

```bash
curl -fsS "https://$APP_HOST/api/healthz"
```
